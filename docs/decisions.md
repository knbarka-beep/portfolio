# Decisions

Small choices made during the build. Each one: what, why, and the alternative.

| # | What | Why | Alternative |
|---|------|-----|-------------|
| 1 | Next.js 16.4 with App Router, Tailwind 4 and TypeScript, made with create-next-app. | The prompt asks for it, and it is the same stack as the three projects. | Plain HTML. Rejected: the CV route needs a server. |
| 2 | Cache Components (on by default in the template) turned off. | Every page is static text built once. The older model, `generateStaticParams` with `dynamicParams = false`, is simpler to explain and turns unknown languages into a 404. | Keep Cache Components. It adds a caching layer this site does not use. |
| 3 | `experimental.globalNotFound` turned on. | The root layout sits under `app/[lang]`, so a URL that matches nothing needs its own 404 page. This is the case the Next.js docs name for it. | A catch-all route. More code for the same result. |
| 4 | Scaffolded in a temporary folder and copied in. | `private/` already held Knut's CV, and create-next-app refuses a folder with files in it. Nothing in `private/` was read or moved. | Move private/ out and back. Rejected: touches the CV. |
| 5 | `/` picks the language from the browser's Accept-Language header: `da` gives /da, `nb`, `nn` or `no` give /no, anything else /en. The first supported language in the visitor's ranked list wins. Temporary redirect (307). | A Danish employer lands on Danish text without clicking. 307 because the target depends on the visitor. | Always /en. Simpler, but a Danish reader then has to switch. |
| 6 | Norwegian pages live at /no but declare `lang="nb"` and hreflang `nb`. Other languages: `en-GB` and `da`. | "no" is the address the prompt asks for; "nb" is the correct code for bokmål. | `lang="no"`. Less precise for screen readers and search engines. |
| 7 | No cookie for the CV: the code is asked for every time. | No cookie banner, nothing to expire, and the server stays stateless. Employers download the CV once. | A signed cookie after the first right code. More code for little gain. |
| 8 | CV route logic in `lib/cv.ts`, separate from the Blob read in `app/api/cv/route.ts`. Tests run the logic with a fake PDF. | The test never needs Blob, the network or Knut's PDF. | Mock `@vercel/blob` in the test. Harder to read. |
| 9 | Local test of the real route: only in `next dev`, and only if `CV_DEV_FILE` names a file. No path to `private/` is written in the code. | A hard-coded path could make the build tracer copy the PDF into the server bundle. An env var leaves nothing to trace. | Read `private/cv.pdf` directly in development. Rejected for that reason. |
| 10 | Whether the CV can be downloaded (passcode and Blob token set) is read when the site is built. | Pages are static. Setting the passcode in Vercel is followed by a redeploy anyway (Part B). The route itself also answers "on request" if anything is missing at run time. | Ask the server on every dialog open. One more request for nothing. |
| 11 | Constant-time compare on SHA-256 hashes of both codes. | `timingSafeEqual` needs equal lengths; hashing gives that without leaking the length. | Plain `===`. Leaks timing, even if only in theory. |
| 12 | CV page link colour: Apple's link blue, #0066CC light (5,57:1 on white, 5,11:1 on #F5F5F7) and #2997FF dark (6,96:1 on black, 6,0:1 on #161617). Buttons near-black #1D1D1F (light) and #F5F5F7 (dark). | Passes WCAG AA in both themes and reads as "link" without decoration. | A project accent. Rejected: the CV page belongs to no single project. |
| 13 | Secondary text #6E6E73 light (5,07:1 on white, 4,66:1 on #F5F5F7) and #A1A1A6 dark (8,16:1 on black). | Apple's greys; AA in both themes. | #86868B. Fails AA on grey in light mode. |
| 14 | Project accents from each repo's `web/styles/tokens.css`: variance-cockpit #1F5F6B / #6FB0BB, startup-runway #2A5788 / #7FA6D6, aml-queue #5E6B2A / #A9B86A (light / dark). Button text white in light, #141412 in dark. | Same values the dashboards use, so the page and the dashboard feel like one product. Contrast is 5,8:1 or better in both themes. | One accent for all. Loses the link to each dashboard. |
| 15 | Screenshots: latest redesign shots from each repo, cropped to the top 1440 x 900. variance-cockpit `docs/screenshots/redesign/desktop-{light,dark}-after.png`, startup-runway `redesign-v2/desktop-light-after-fix.png` and `desktop-dark-after.png`, aml-queue `redesign/after-desktop-{light,dark}.png`. next/image serves them as AVIF or WebP. | The full-page shots are up to 2.771 px tall; the top shows the headline, KPIs and main chart, which is what a reader needs. | Full height. Too long for a hero image. |
| 16 | Both theme screenshots are in the HTML; CSS hides the one that does not match. The dark one is lazy-loaded, so it only downloads when shown. | Switching theme swaps the image instantly, with no script. | Swap `src` in JavaScript. Flickers. |
| 17 | Tabular figures only on dates and the project-card numbers, not on all body text. | In Inter, tabular figures also widen hyphens, so "month-end" looked like "month - end". | Global `tnum`. Rejected for that reason. |
| 18 | Profile in three sentences. It leaves out the KYC and AML work from the CV summary; that stays in Experience and Skills. | The prompt names Ria's work only for Experience. Keeping KYC out of the Profile keeps distance from the AML project. | Mention KYC in the Profile. |
| 19 | Degree and course names stay in English in Danish and Norwegian, except where a plain translation is obvious (the Norwegian bachelor, the Noroff degree). | Official names. Translating course titles invites mistakes. | Translate all. |
| 20 | Project numbers keep their source form in all languages: "DKK 0,25 mio." (DA) and "DKK 0,25 mill." (NO), euro amounts as €1.579.630. | The same digits as the README, so the numbers test can check them in every language. | Local currency formats like "1.579.630 €". |
| 21 | Danish banned-word list does not include "rejse" alone, only "rejsen" (and "reisen" for Norwegian). | "Rejse kapital" means "raise capital", which the runway page needs. "The journey" is "rejsen". | Ban "rejse". Blocks a correct finance term. |
| 22 | Mobile menu is a panel under the nav bar, closed by the button, Esc or a link. Breakpoint at 1024 px, because five nav items plus language and theme do not fit below that. | Simple, no dialog needed, and the page behind stays readable. | Full-screen sheet with focus trap. More code. |
| 23 | Open Graph images are drawn at build time with `next/og`: per language for the start page (name, one line, three screenshots) and per language and project for project pages (name over the screenshot). | Static PNGs, no function call when shared. | One static image. Loses the per-language text. |
| 24 | QA script talks to headless Edge over the DevTools protocol with Node's built-in WebSocket, like the three project repos. | No new dependency. | Playwright. Large download for a few checks. |
| 25 | Inter from `next/font/google`, which downloads the font at build time and serves it from the site itself. | Self-hosted as the prompt asks, no request to Google from visitors. | Local font files. Same result, more files. |
| 26 | `vercel.json` sets `"framework": "nextjs"`. | The new Vercel project was created with the preset "Other", which would have built and served the wrong output. Setting it in the repo makes it visible and versioned. | Change it in the Vercel dashboard. Works, but is invisible in the code. |
| 27 | Branch renamed from `master` (create-next-app's default) to `main` after the first push; `master` deleted on GitHub. | The prompt and the Vercel production branch use `main`. | Keep `master`. |
| 28 | Final address https://knutbarka.vercel.app (the first choice was free). It is the default in `lib/site.ts` and drives metadataBase, og:url, the sitemap and robots.txt. | One place to change if a custom domain comes later. | Set it only as an env var in Vercel. Then a local build would show the wrong URL. |
| 29 | Blob store named `knutbarka-cv` (Vercel requires at least 5 characters, so `cv` was refused), region iad1, connected to Production and Preview. | Same region as the server function. | fra1. Closer to Denmark, but the function runs in iad1. |
| 30 | Theme bug fix: `ThemeSync` in the shared `[lang]` layout re-applies the saved theme (or the system setting) in a layout effect after every navigation. The inline `<head>` script still sets it before the first paint of every page load. | Each language has its own root layout. When Next.js swaps root layouts on a client-side navigation (EN to DA), React resets the attributes on `<html>`, which dropped `data-theme`, so the page fell back to light. A layout effect runs after React's change and before the browser paints, so no light frame is drawn. The QA check reproduced the bug before the fix (theme lost on every switch, light frames drawn) and passes after it. | Keep the theme in a cookie and render it on the server. Rejected: the site has no cookies, and the pages are static. |
| 31 | Nav and language switcher keep using `next/link` (client-side navigation). | Already the case; the bug was not caused by full page loads. | Plain `<a>` links. Slower and would reload fonts. |
| 32 | Hero text in two lines: line 1 says who and when (degree, SDU, graduation), line 2 in grey says what the page holds. Danish: "Kandidatstuderende i Economics and Business Administration på SDU, Odense. Færdig i sommeren 2027." / "Mit CV og tre økonomiværktøjer, som jeg har bygget med AI." Norwegian: "Masterstudent i Economics and Business Administration ved SDU i Odense. Ferdig sommeren 2027." / "CV-en min og tre økonomiverktøy jeg har bygget med AI." The degree name stays in English, as in Education. The start page Open Graph image now uses line 1. | Text as asked; the translations follow the same plain style. | Translate the degree name. Inconsistent with Education. |
| 33 | Hero visual: the three dashboards as a layered stack (AML queue at the back, Variance cockpit in front), each 78 % of the column wide and offset by fixed percentages. It sits to the right of the text from 1024 px and under the buttons below that. It uses the same screenshot frame as the rest of the site, so it follows the theme. Each layer links to its project page. Fade and rise once on load (600 ms, staggered 100 ms); off under reduced motion. Hover lifts a layer 4 px. | Shows the work in the first second without pushing the buttons down. QA checks the buttons stay above the fold at 1440 x 900 (bottom at 521 px) and 375 x 667 (bottom at 451 to 479 px) in all three languages. | Screenshots between the name and the buttons on mobile. Rejected: it pushes the buttons below the fold. |
| 34 | No portrait: `public/me.jpg` does not exist, so this step was skipped. Adding the file later needs a small change in the hero (a round image next to the name). | As asked. | Placeholder image. Rejected: an empty circle looks unfinished. |
| 35 | Hero width matches the 1080 px column of the nav and every section below, so the name lines up with the rest. | A wider hero broke the left edge. | Wider hero for a bigger stack. |
| 36 | Every link that leaves the site goes through one component, `ExternalLink`: `target="_blank"`, `rel="noopener noreferrer"`, a small arrow icon, and hidden text for screen readers ("(opens in a new tab)", "(åbner i en ny fane)", "(åpnes i en ny fane)"). It covers the live dashboard, GitHub, case sheet, footer, LinkedIn and the LinkedIn link in the CV dialog. Internal links keep `next/link` and the same tab. | As asked. One component means no link can forget part of it, and the QA checks every page. | Add the attributes by hand on each link. Easy to miss one. |
| 37 | The LinkedIn logo button in the hero has no extra arrow; it gets hidden text "LinkedIn (opens in a new tab)" instead of the old aria-label. The case sheet link shows the arrow instead of its chevron. | An arrow next to a logo looks cluttered, and two marks on one link is noise. | Arrow everywhere. |
| 38 | Hero stack in tab order front to back (Variance cockpit, Startup runway, AML queue). z-index draws them back to front. | Keyboard focus should reach the layer you see first. | Back to front in the code. Focus lands on the hidden layer first. |
| 39 | QA can run just the hero and theme checks with `QA_ONLY=quick`, and logs the full text of any page error. | Faster debugging; the first run showed an error with no message. | Always the full run (about 4 minutes). |
| 40 | The CV comes in three languages. The dialog has an English, Dansk, Norsk choice (plain radio buttons styled as one bar) that starts on the page language. `/api/cv` takes `lang` (en, da or no, anything else means en) and sends `cv/Knut-Barka-CV-<LANG>.pdf` from Blob, or the English file if that language is missing. In `next dev` it reads `private/cv-<lang>.pdf`; `outputFileTracingExcludes` keeps `private/` out of the build, and the PDF test still checks the output. This replaces `CV_DEV_FILE` (decision 9). The start-page project cards now show the project line from the CV, and the CV sections use the CV wording. One education line, about semester and exam projects at Noroff, is left out, because the repo rules allow course names only. | As asked: one CV per language, and the site says what the PDF says. Radio buttons give keyboard and screen reader support for free. | A separate download button per language. Three buttons in a small dialog is more clutter. |
| 41 | Replaces the language choice in decision 40. The visitor enters the code once. `/api/cv` with `check: true` answers 204 on a right code without sending a file; wrong code is unchanged. The dialog then shows English, Dansk and Norsk buttons, page language first, and stays open after each download. The code is held in memory (a React ref) and sent with each request; closing the dialog clears it. The Noroff line on semester and exam projects is back, and CLAUDE.md now says the rule is about publishing copies of assignments, not describing them on a CV. | As asked. A check-only call means a right code shows the buttons without downloading a file the visitor did not choose. | Download the page-language CV on the first submit, then show the other two. Rejected: the visitor did not pick it. |
| 42 | The three CV buttons share one outline style (`pill-choice`) and fill only on hover or keyboard focus. A check mark, with hidden text for screen readers, marks each language downloaded in this dialog session. Page language stays first. | As asked: no language is pushed as the default. | Keep the page language highlighted. |
| 43 | A small privacy page at `/[lang]/privacy`, linked from the footer and listed in the sitemap. It states facts only (no cookies, analytics or tracking; theme in the visitor's browser; Vercel's technical logs; CV only with the code; contact on LinkedIn) and names no law. | Visitors and recruiters can see what the site does with their data. | No page. Rejected: the footer line was asked for. |
| 44 | `.github/dependabot.yml` checks npm weekly. Dependabot alerts and security updates are switched on in the repo settings. | Security fixes for dependencies arrive as pull requests. | Check by hand with `npm audit`. Easy to forget. |
| 45 | Dependabot group `react`: react, react-dom and @types/react* are updated in one pull request. | react and react-dom must match; a lone react-dom bump failed npm install on the Vercel preview. | Close mismatched pull requests by hand each time. |
